## ローカル検証

実施結果: 専用自動テスト31件成功。Astro checkはエラー0・警告0（既存コードのhint 7件）。通常ビルドと独立デモビルドが成功し、通常distにデモゲームとlive JSONが入らないことを確認した。

ブラウザーではデスクトップと390px幅を確認し、スタッフの3択→PC保存→公開JSON→公開表示、受付停止時のボタン無効化と公開側の停止表示、受付再開を操作した。スタッフ画面と公開ページはいずれもHTTP 200。PC内のQR出力も生成した。これらはローカル模擬経路での検証であり、会場iOS/Androidや実FTPホストの検証ではない。

`npm run test:congestion` で入力不正、同時更新、停止競合、保存失敗、正常バックアップ、破損停止、再起動復元、二重起動、日別NULL化、確認と生成の鮮度分離、HTTP時刻、未知/欠落ID、転送中の更新、転送失敗、rename失敗、HTTPS不一致を検証する。実FTP転送の代わりに模擬クライアントを使用し、本番環境に変更を加えない。

`npm run check` と `npm run build` で既存の静的出力を確認する。Windowsのこの作業環境ではサンドボックス内のAstroモジュール解決・ファイルrename・ループバック通信が制限されたため、許可された通常実行環境で確認した。

デモは同じ状態保存/API/公開スナップショット処理を使用するが、実ホスト転送の代わりにPC内の別領域へ保存する。通常のdistへデモやlive JSONは入らない。初回デモ状態はサンプルであり、現地確認とは扱わない。

## 本番開始の前提

2026年10月16日、最新masterと同じ `ade8c8c` を基にdevへ統合した。既存のAstro 7.3.5・共通ナビ・固定されたActionsの参照を維持し、統合後に `npm ci`、専用テスト31件、`npm run check`（エラー0・警告0、既存ヒント3件）、development設定の `npm run build` が成功した。配信カタログはdevelopment・デモ無効・正式ゲーム0件で、`dist/live/` を含まない。

正式データ・日時、会場の経路、原子的なホスト置換、公開キャッシュ・Date、配信共存の確認を実施し、設定の対応を確認してから本番開始する。これらはローカルテストでは代替できない。条件が不成立なら代替案を選んで両文書を改訂する。追加の承認フローは設けない。
