# ゲーム展示・混雑情報 実装仕様

2026年10月14日。ユーザー提供の同日改訂設計・計画に基づくローカル実装。会場ネットワーク・実ホスト・正式ゲーム情報は未確認。本書は実装済みの契約と未確認事項を記録するもので、本番稼働の証明ではない。

## 構成

静的な `/games/` にゲーム紹介・プレイ時間・場所を出力する。待ち時間をプレイ時間へ含めず、混雑から待ち時間を計算しない。PC・スマホ両ナビ、縁日班アトラク紹介、サイトマップから案内する。既存の静的Astro配信と `master` / `dev` の対応を維持する。2026年10月16日に最新の `master` を取り込み、Astroのpackage指定 `^7.3.5` を含む既存の依存関係を維持した。Node実行・CIは24。

スタッフは `http://<LAN-IPv4>:8787/staff/congestion/?game=<id>` を開く。画面・CSS・JSはPC内で完結する。認証・PIN・担当権限はなく、PCへ到達できる人は任意の登録ゲームを更新できる。Origin・Host検証は別サイトからの誤送信を防ぐためで、本人確認ではない。公開ページは同一オリジンの `/live/congestion.json` のみを取得し、会場PCへアクセスしない。

## PC API・保存

`GET /api/status` は登録ゲーム、保存値、確認時刻、受付・セッション、保存版、転送完了とHTTPS反映確認の結果を返す。認証情報、ローカルパス、FTP応答本文は返さない。

`POST /api/games/<id>/congestion` は `{ "level": "low" | "normal" | "high" }` のみ受付。同一オリジン、JSON Content-Type、2KB以下、登録ゲーム、開催区間、受付開始を検証。CORS許可や破壊的APIは設けない。

保存と運営コマンドは同じPromiseキューで直列化する。確定した最新状態をメモリーとディスクへ反映し、永続保存成功後にだけ `ok:true` を返す。版番号は10進文字列。再選択も確認時刻と版を進める。保存は同じディレクトリに一時書き込み→sync→close→rename。直前の正常状態を先に `.bak` へ保存。置換失敗で古い状態を削除せず、失敗した更新を成功扱いにしない。

起動時に形式・環境・イベント・カタログ・セッションを照合する。異常は明示停止。状態不在かつバックアップありも自動初期化しない。同じ状態領域への二重起動は排他的ロックで拒否。再起動で確認時刻は変更しない。日別セッション切替は全件NULLにする。`stop` は停止、`reset` は停止とNULL化、`resume` は時間内の再開。いずれも同じ実行プロセスの標準入力で操作する。

スタッフ画面は確定した現在値、送信中、PC保存、公開反映を分ける。結果不明では再取得し、自動再送しない。UIの色に加えて文字と記号を表示する。

## 発行

15秒周期。発行は1本だけで、開始時点の最新状態を取り出す。変更なしでも `generated_at` を進め、`observed_at` と `saved_version` は維持。転送中の通常更新は次の周期に最新状態へ集約する。更新が頻繁でも進行中の発行を無限に取り消さない。セッションや受付状態が転送中に変わった場合は古い一時ファイルを最終名へ交換しない。

設定上の環境・URL・イベント・日程・転送先の対応を起動時に照合する。実機確認前は `transfer.verified:false` とし本番用起動を拒否する。各発行では公開カタログも照合し、不一致なら転送しない。インターネット障害は発行側で扱い、起動後のローカル保存を妨げない。

`basic-ftp` で同一 `/live/` 内の一時名へ転送し、最終名へrenameする。先行削除や別環境へのフォールバックは行わない。TLSは証明書を検証する。カタログ照合・FTP・HTTPS読み直しの全体を10秒で打ち切る。失敗時は2、4、8…最大60秒間隔で、古いキューを作らず最新状態だけを再試行する。

最終名交換の時刻・版は `last_transfer`、HTTPSで同じ内容を確認した時刻・版は `last_success`。HTTPSで旧版が返る場合や読み直し失敗は公開成功にしない。

## 公開JSON

```json
{
  "schema_version": 1,
  "environment": "development",
  "event_id": "example-event",
  "catalog_id": "64文字のSHA-256",
  "session": {
    "id": "example-day",
    "starts_at": "2026-11-01T00:00:00.000Z",
    "ends_at": "2026-11-01T07:00:00.000Z",
    "accepting": true
  },
  "saved_version": "18",
  "generated_at": "2026-11-01T01:25:15.000Z",
  "games": [
    {
      "id": "example-game",
      "level": "normal",
      "observed_at": "2026-11-01T01:25:00.000Z"
    }
  ]
}
```

上記は説明用。選択前のsessionはnull。ゲーム初期値はlevel/observed_atともnull。設計書の契約に加えて、PCとページの内容を厳密に揃えるためcatalog_idを検証する。

公開取得は15秒＋0〜3秒ジッター。cache:no-store、毎回異なるクエリー、5秒タイムアウト。非表示中は停止し、復帰直後は値を未確認に戻して即取得する。HTTP Dateと単調増加する経過時間で判定し、閲覧端末の時計は使わない。Date欠落、未来時刻、形式・イベント・環境・カタログ・セッションID/区間の不一致、古い版への巻き戻りは使わない。Dateの秒精度について1秒の丸めだけを許容する。

未登録IDは無視、欠落IDはNULL。時間外・停止を優先し、未確認、10分以上の現地確認、最新3値を区別する。生成から60秒で配信停止の可能性を示して3値を隠す。通信失敗でも静的紹介は残し、以前の混雑を現在値として表示しない。通常反映45秒以内が目標で、実ホストでは未測定。

本番・テスト両workflowで既定除外を保って `live/**` と `**/live/**` を追加。`dangerous-clean-slate` は使用しない。実行時JSONは静的成果物に含めず、更新ごとのGitコミットやビルドを行わない。workflowの「Deploy via FTPS」という名前は暗号化の根拠にしない。既存のprotocol未指定を維持し、実ホストの対応確認後に変更する。
